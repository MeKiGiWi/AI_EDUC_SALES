# PROJECT_DIRECTION

## Новый вектор проекта

Проект `AI Sales Academy` переводится с web/Next.js направления в сторону `React Native mobile-first` продукта.

Текущий репозиторий больше не рассматривается как целевая Next.js-платформа. На этом этапе задача репозитория:

- зафиксировать мобильную продуктовую модель;
- подготовить frontend-моки;
- описать typed data;
- подготовить контракты для будущей интеграции с Python backend;
- закрепить зеленую дизайн-систему как единый визуальный язык продукта.

## Почему mobile-first важнее

Mobile-first подход важнее для MVP, потому что ключевые пользовательские сценарии Академии продаж происходят в коротких и частых сессиях:

- быстро пройти тренировку между встречами;
- открыть диалоговый симулятор с телефона;
- получить моментальную обратную связь после ответа;
- посмотреть персональный план развития без входа в тяжелый кабинет;
- использовать приложение в полевых, кабинетных и смешанных сценариях обучения.

Для продукта, связанного с обучением, симуляцией диалога и персональной практикой, мобильный интерфейс лучше соответствует реальному ритму ученика и руководителя.

## MVP surfaces

В MVP должны быть предусмотрены следующие продуктовые поверхности:

- мобильный кабинет ученика;
- мобильный симулятор диалога;
- мобильная база знаний;
- мобильная обратная связь и план развития;
- кабинет руководителя;
- кабинет HR/L&D;
- администрирование;
- отчеты и выгрузки.

## Технологический контур

- Frontend target: `React Native`.
- Предпочтительный стартовый стек: `Expo + TypeScript`.
- Backend target в будущем: `Python` (`FastAPI` или аналогичный Python backend).
- На текущем шаге backend не создается.
- В этом репозитории не нужно реализовывать Node backend, API routes или server actions.

## Что это значит для следующих итераций

Следующие Codex-итерации должны:

- мыслить экранами и мобильными сценариями, а не web-страницами;
- проектировать typed mock data и service layer;
- использовать переиспользуемые мобильные компоненты;
- ориентироваться на green AI Sales Academy style;
- держать все действия пользователя осмысленными и видимыми.
